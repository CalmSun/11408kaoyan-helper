## Windows 本地构建修复：pdfrx 降级 2.6.6（16:20 后，commit 79eacc6）

### 根因（排查了整整一下午）
- 用户装好 VS Build Tools 2022 后，`flutter run -d windows` 报 `Target build_hooks failed: Building native assets failed`。
- **根因是 pdfrx 2.11.0 → pdfium_dart 0.4.x 的「原生资产构建钩子」**：`hook/build.dart` 会先用 cl.exe 编译一个
  `pdfrx_pdfium_gate` C 门闩库（经 native_toolchain_c 调 vcvars64.bat 解析 MSVC/SDK 环境），这步在部分机器上环境解析
  失败 → cl.exe exit 1 → 整个 build_hooks 失败 → flutter_wrapper_*.vcxproj 没生成 → 后续 MSB4025 + LNK1104 连锁报错。
- 次要坑：pdfium_dart 还会从 **github.com/bblanchon/pdfium-binaries** 下载 pdfium 二进制（~40MB），国内直连超时，
  **必须走本地代理**（用户 Clash 在 `127.0.0.1:7897`），下载钩子已支持 `https_proxy`/`http_proxy` 环境变量。
- 排查排除了：VS 工具链（手动 cl.exe 编译 gate 成功）、Windows SDK（10.0.26100.0 已注册，vcvars64 优先读 WOW6432Node）、
  开发者模式（已开）。沙箱里的 reg.exe 黑名单会让 vcvars64 找不到 SDK，是**沙箱假象**，非用户环境问题。

### 修复
- `pubspec.yaml`：`pdfrx: ^2.11.0` → `pdfrx: 2.6.6`（最后一个「只下载不编译」的版本；2.7.0 起才引入 gate 编译）。
  降级后 pdfium_dart 0.4.1→0.3.1（无 gate 编译）、pdfium_flutter 0.3.1、pdfrx_engine 0.6.1，native_toolchain_c 整个移除。
- 用户本地构建命令（关键两步）：
  ```
  set HTTPS_PROXY=http://127.0.0.1:7897
  set HTTP_PROXY=http://127.0.0.1:7897
  flutter run -d windows
  ```
- **本机实测 `flutter build windows` 通过**（185s），产出 `kaoyan_helper.exe` + `flutter_windows.dll`(21MB) +
  `pdfium.dll`(7MB) + audioplayers/url_launcher 插件 dll。CI（GitHub runner 直连 GitHub）无需代理。

### 后续注意
- 想升回 pdfrx 2.7+，需先解决 native_toolchain_c 的 vcvars64 环境解析（或在 CI 环境验证可行后再升）。
- 覆盖 v3.6.5 tag 时三端构建会用 pdfrx 2.6.6，Linux/Android 走 pdfium_dart 0.3.1 下载，CI 上无代理问题。

  倒计时 `_tipItem`（科目名）、大纲 `_subjectCard`（科目名）都加 Flexible + ellipsis。
