# 2026-08-16

## 学习资料页（Materials.vue）文档预览/进度重构 → v3.4.7

- 重构 `src/renderer/src/views/Materials.vue` 的 docx/xlsx 预览与文档工具栏，并修复“文档浏览获取当前页码/记录阅读进度”失效问题。已提交并 push 到 `origin/main`（commit `b681ae6`）。

### 根因（关键可复用结论）
- `@open-file-viewer/core`（v0.1.40）的 office 插件里 `.ofv-viewport` 样式为 `overflow: visible`，**不是滚动容器**。旧代码 `getDocumentScrollEl()` 先查 `.ofv-viewport`/`.ofv-table-scroll`，结果把外层挂载容器当滚动容器 → `scrollTop` 恒为 0、进度卡 0、IntersectionObserver 根错误 → 页码/进度无法跟踪。
- 正确做法：从页面块（`.ofv-docx-page-frame` 等）向上找最近的“可滚动祖先”作为真实滚动容器。库内部 `goToRenderedPage(panel, selector, page, panel)` 中 `panel` 即滚动容器且包含页面块。

### 官方 API 用法（已验证于 node_modules 的 index.d.ts）
- `createViewer(...)` 返回 `FileViewer`，实例方法含 `goToPage(page): boolean`（docx 走 officePlugin 的 goToRenderedPage，有效）、`destroy()` 等。
- `PreviewOptions.initialPage?: number`：打开时定位到 1-based 页码（恢复阅读进度）。
- 工具栏 `toolbar.render(ctx)` / `toolbar.actions[].onClick(ctx)` 的 `ctx` 提供 `goToPage(page)`、`viewport`、`setZoom`、`search`、`fullscreen` 等；但 `ctx` **不**暴露 `page`/`totalPages`，页码需自行用页面块 + IntersectionObserver 跟踪。
- 页面块选择器（库内部）：`.ofv-docx-page-frame, .ofv-docx-textbox-page, .ofv-msdoc-page, .ofv-slide, .ofv-ppt-binary-slide`。
- PDF 仍用 Chromium PDFium `<iframe>`（因 pdfjs-dist 6.x 在 Electron 28 下 ES2025 兼容问题），不要切到 open-file-viewer 的 pdfPlugin。

### 视频
- 视频播放用原生 `<video>` + Web Audio 增益，保持原样未改（gain 功能 open-file-viewer 无对应能力）。
