### 核心技术：为什么之前"像磨砂不像玻璃"
关键不在透明度，而在 **`backdrop-filter: url(...)` 拿不到位移图**，只能得到模糊。
正确手法（库的做法）：
```
同一个元素上同时带
  backdrop-filter: blur() saturate() contrast() brightness()
  filter: url(#lg-glass-N)
```
Chromium 会把 backdrop-filter 的结果当作 filter 的 SourceGraphic → 背景先被真实采到、再被折射。
实现在 `src/renderer/src/utils/liquidGlass.ts`。

位移图运行时用 canvas 按圆角矩形 SDF 现算（R=x 位移、B=y 位移、A=离轮廓距离），
`feDisplacementMap` 三通道位移量略不同产生色差；中心零形变、边缘最大 → 边缘透镜。

### 实测结论（探针页验证，非推测）
- `feImage` + PNG data URI 位移图在 `filter: url()` 中**可用**（棋盘图边缘明显弯折+色散）
- `backdrop-filter` 输出确实进入 `filter` 的 SourceGraphic
- **`isolation: isolate` 不会切断背景采样**（与 `z-index:0` 表现一致）—— 之前担心错了
- 副作用：`brightness()` 是乘性的，会把明暗差一起放大。必须先 `contrast(<1)` 压窄带、
  再 `brightness(>1)` 抬亮，顺序反了会拉大卡内明暗差。

### 文字对比度：靠抬背景，不靠加厚玻璃
清透玻璃压在高反差照片（亮天空 + 近黑树影）上文字必然看不清。
解法是在滤镜链里压缩背景动态范围：`blur(7px) saturate(155%) contrast(0.32) brightness(1.40)`。
实测卡片玻璃面亮度 0.675，text-1 7.5:1 / text-2 6.5:1 / text-3 由 3.25:1 提到 4.3:1。
（对比度用 `node scripts/measure-luminance.cjs` 自解码 PNG 测量，已用完删除。）

## v3.6.5 第二轮优化（同日，掉帧 + 黑阴影 + 通透 + 全站覆盖）

### 掉帧根治（10.6 → 100 FPS）
第一版上线实测静止状态 10.6 FPS、最差单帧 110ms。用 8 张卡片逐步定位，根因唯一：
**`feImage` 每帧都要解码位移图 PNG**。尺寸-帧率：512²→4.2、128²→57.8、64²→113.8 FPS。
位移场是平滑梯度，小图拉伸视觉等价 → 位移图长边压到 **72px**。
配合：视口外卡片由 `IntersectionObserver` 关掉 warp（不再滚动逐个 getBoundingClientRect）。

### 修「卡片中间黑色阴影」
第一版位移图 A 通道编码"离轮廓距离"（中心 alpha=0），SVG 滤镜按预乘 alpha 处理，
透明像素 RGB 被当 0 → 位移量变成常量偏移 → 卡片中间出现形似位移图的灰块。
修法：A 恒为 255，中心位移靠 SDF 梯度在中央天然为 0。

### 滤镜链简化（参照 liquid-glass-vue）
去掉第一版自己发明的「中心保持原样 / 只有边缘折射」两段合成（feComposite），
那套合成正是灰块的来源。参考库本身没有这层——它的位移图中心梯度=0 自然归零。

### 其他修复
- REGION 与滤镜区域比例不一致：FILTER_MARGIN_PCT 从 18 改 10 时 REGION 忘了同步（1.36→1.20）
- 内容卡片移除白色 text-shadow 光晕：它让深色文字发灰，副作用大于收益

### 验收结论
- 黑色阴影消失、玻璃质感在（透背景 + 边缘高光）、无白块/黑块/倒置/重叠
- 标题文字实测亮度差 132.9（可读阈值 60）；侧边栏文字修复后可读
- 视觉模型对「文字偏淡」的判读多次误判，最终用 `node scripts/measure.cjs`（自解码 PNG
  分位数亮度）客观测量判定，用完删除

## v3.6.5 第三轮修复（同日，显示异常 + 分层纠正）

### 异常根因
用户报「显示效果明显异常」：内容卡片背景消失、正文文字直接叠在壁纸上几乎不可读。
根因：第一版把**所有内容卡片**都接入折射层、白纱降到 0.16，正文压在花哨壁纸上必然翻车。

用户给了参照 https://liquidglassdesign.com/zh/what-is-liquid-glass ，核心原则：
**「玻璃是给浮在内容之上的那层用的，不是给内容本身用的；正文不行」**。苹果自己都因
可读性在 26.1 补了不透明着色开关。

### 修复（分层）
1. `DEFAULT_SELECTOR` 只保留浮层：`.side-nav / .titlebar / .pomodoro-mini`。
   内容卡片（card/glass-card/stat-card/algo/word/formula-card）全部退出折射层，
   恢复 `--glass-bg`（0.72 实心）+ backdrop-filter blur。
2. `body.liquid-glass` 超通透档不再降底色：`--glass-bg` 0.18→0.78（浅）、0.08→0.72（深），
   玻璃感改由更强的 blur(25px)/大圆角/阴影承担，不靠降底色。
3. `--glass-bg-lg`（0.16 白纱）成为死变量（浮层走 chrome 档、内容卡无 .lg-on），无害未清理。

### 验收
客观测量确认：所有卡片浅色实心底、文字可读；浮层折射正常、导航可读。
视觉模型多次把「0.72 半透明 + blur 的玻璃拟态」误判为「透明/叠壁纸」，以像素测量为准。
