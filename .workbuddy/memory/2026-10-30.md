## v3.6.5 设计重构（液态玻璃）+ 去重 + 发布

- 目标：仿 liquid-glass.ybouane.com 重构设计风格，清无用代码，不影响功能与性能，版本 3.6.5，推 GitHub。
- **关键决策：不引入 `@ybouane/liquidglass` WebGL 库**。它靠 html-to-image 逐帧栅格化 DOM + 多 pass shader，
  数百条列表项的页面必掉帧，且每实例独占一个 WebGL 上下文。改用 CSS 合成层复刻同一光学语言：
  `backdrop-filter`（blur+saturate+brightness）负责折射，伪元素负责镜面/菲涅尔/色差，
  `::before` 承载全部高光、`::after` 只放极轻噪点。零额外 DOM、零 JS 逐帧开销。

  Materials/Music 用裸 `<div class="glass-card">` 只好各复制一整套玻璃样式 + 4 段 `body.liquid-glass` 覆盖）。
  删除两处重复共 137 行，仅保留 padding/flex 布局；Music 必须保留 `overflow: visible`（v3.2.6 合成层修复）。
- 变量收敛：旧 `--glass-edge-highlight` / `--glass-highlight-top|corner|bottom` → `--glass-rim-top|bottom|side` /
  `--glass-specular` / `--glass-top-glow` / `--glass-bottom-glow` / `--glass-chromatic` / `--glass-noise`。
  改令牌时必须全库搜 `var(--glass-` 确认无断引用。
- 清死代码：`.gradient-text`、`.number-emphasis`、裸 `.glass`；SideNav 的 `.theme-*`/`.user-*` 7 段
  （v2.7.0 起主题与用户栏已在顶栏）。
- 「液态玻璃」开关重新定位为**超通透档**（基础样式已是玻璃质感），持久化键 `kaoyan_liquid_glass` 不变。
- 性能红线（后续改样式勿破）：每卡一层 backdrop-filter；`.glass-lite` 无滤镜；hover 只用 box-shadow 禁 transform。
- 验证手段：`npm run preview` 起 dist 静态服务 + 自建 `__preview.html` 挂真实构建 CSS，
  用浏览器 MCP 截 深/浅 × 默认/超通透 四组对照（验证完删除该页）。注意：预览窗口仅 ~800px，

## v3.6.5 第二轮（同日，同一话题的追改）：毛玻璃 → 真折射（用户要求覆盖 3.6.5，不另起版本号）

用户反馈"还是不够通透"，并明确"不要毛玻璃，要液态玻璃"。根因不是透明度，是**用 blur 模拟玻璃**。

### 实测结论（重要，别再重复试错）

| 方案 | 结果 |
|---|---|
| `backdrop-filter: url(#turb)` + feTurbulence/feDisplacementMap | ✅ 生效。15 张带滤镜卡片同时 144FPS（显示器上限）。这是当前采用方案 |
| `feImage` 位移图做"透镜放大" | ❌ 在 backdrop-filter 里不生效，且帧率掉到 10-17FPS |
| `@ybouane/liquidglass` WebGL 库（CDN 实测） | ✅ 效果最好，145FPS，能看到树影被真实折射。但结构限制见下 |

### WebGL 库的三条硬约束（源码已核实）

1. 玻璃元素必须是 root 的**直接子节点**（本项目卡片在 `main > 视图 > .grid > 卡片` 四层下）。
2. root 自身背景**不会被采样**，场景必须作为子节点重画一份并对齐滚动位置。
3. `_setupGlassElements` 里 `el.style.overflow = "visible"` 无条件设置 —— 与主内容区 `overflow-y:auto` 直接冲突；
   且所有非玻璃子节点会用 html-to-image 栅格化，深层容器每次重绘几十到几百 ms。

→ 整站接入 = 重写布局模型。若要做，按页迁移（先一页样板）比全站替换安全。

### 设计要点（可复用）

- **可读性靠背景层，不靠玻璃层**：玻璃几乎不染色后，用 `.app-bg-decor` 的白色蒙版（0.44）统一提亮背景，
  深色文字才能在照片暗部上读得清。抬背景 ≠ 抬玻璃，这是"通透 + 可读"能同时成立的关键。
- 浅色主题必须比深色主题白度更高（深色白字天然高对比，可以做到近乎全透）。
- 清透玻璃下文字色阶要整体压深：`--mo-text-3` 从 #6f7889 → #46505f。
- `--glass-wave` 用变量存 `url(#id)`，切档只换变量，不用重写滤镜声明。
- `@supports (backdrop-filter: url(...))` 命中才启用折射；`-webkit-` 前缀不支持 url()，判断要写 `or`。

### 踩坑

- 截图验收时若窗口只有 ~660px，用 `transform: scale()` 缩放整页会在深色渐变上产生**矩形伪影**（缩放重采样），非真实问题。
- 浏览器 MCP 截图偶发 "Current display surface not available"，重试或换 jpeg 即可。
- 提交前发现 `启动开发版.bat` 在工作区被删（非我操作）→ 用 `git checkout -- <file>` 恢复，避免误提交删除。

## v3.6.5 第三轮：自研边缘透镜 WebGL 玻璃

用户要求"追参考站那种边缘透镜并逐页推广"，并授权改技术栈。

### 关键决策：自研，而不是直接用 @ybouane/liquidglass

库的效果确实最好（145FPS），但三条约束卡死本项目（详见前文）。
自研的前提是**换取景方式**：应用背景本来就是「一张固定图/一段渐变」，不是任意 DOM，
所以不需要抓取 DOM —— 着色器按元素屏幕位置直接采样背景即可，滚动只重算位置。

文件：`src/renderer/src/utils/liquidGlass.ts`（约 420 行，含 GLSL）。
App.vue 里 `nextTick(() => initLiquidGlass())`，路由切换与主题切换时 `mount()/refreshTheme()`。

### 踩过的三个坑（务必记住）

1. **canvas 层级**：正确做法是 `.lg-canvas { z-index:-1 }` + `.lg-on { isolation: isolate }`。
   我曾用 `.lg-on > *:not(.lg-canvas) { position: relative; z-index: 1 }`，它覆盖了各视图里
   绝对定位子元素的样式，把整个页面布局撑爆（截图报"超出 10MiB 上限"就是这个原因）。
2. **CSS px 与设备 px**：`gl_FragCoord` 是设备像素，uniform 传的 rect 是 CSS px，
   必须用 `uDpr` 统一换算，否则 DPR≠1 时采样错位。
3. **小卡片被斜面吞掉**：bevel/strength 不能给固定像素值，要按 `min(w,h)` 自适应，
   否则 90px 高的 KPI 卡片整个面都是斜面，渲染成灰块。

### 最重要的一条设计经验

清透玻璃压在高反差照片上（亮天空 + 近黑树影），文字一定看不清。
解法**不是加白**（加了就退化成磨砂），而是**在着色器里压缩背景对比度**：
`col = (col - 0.5) * 0.55 + 0.5 + 0.30` 再叠 0.20 白度。
结构保留（通透），极值被收进窄区间（可读）。深色主题背景柔和，不做压缩。
