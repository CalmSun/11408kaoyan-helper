## 🔍 **技术实现细节**

### 1️⃣ **启动流程重排序（核心改进）**

#### ❌ 旧逻辑（错误）：
```typescript
sourceopen → addSourceBuffer → pumpTrack → immediate play()
           ↑
       Metadata 未加载！
```
**结果**：Video Element 在 metadata 未就绪时调用 play()，导致无法解码和起播。

#### ✅ 新逻辑（正确）：
```typescript
sourceopen → addSourceBuffer → pumpTrack
                     ↓
              wait for canplaythrough + loadedmetadata
                     ↓
              verify video.readyState >= 3 && mediaSource.readyState === 'open'
                     ↓
              setTimeout(100ms, () => { seek() + play() })
```
**效果**：确保元数据、buffer 状态、解码器全部就绪后才触发播放。

### 2️⃣ **智能 Codec 回退机制（avc1/hevc/any）**

```typescript
const codecFallbackOrder = ['avc1', 'hev1', 'any']
for (const codecType of codecFallbackOrder) {
  // 1. 按优先级过滤视频轨道
  const filtered = supportedVideo.filter(t => encodeScore(t.codecs) > 0)
  
  // 2. 同组内选最高带宽（最清晰）
  const sorted = [...filtered].sort((a, b) => b.bandwidth - a.bandwidth)
  const trialTrack = sorted[0]
  
  // 3. 实际测试 codec 可用性（临时 SourceBuffer + append 初始化 segment）
  try {
    const sb = tempMs.addSourceBuffer(trialMime)
    const initSegment = await fetch(trialTrack.baseUrl, { Range: 'bytes=0-2MB' }).then(r => r.arrayBuffer())
    sb.appendBuffer(new Uint8Array(initSegment).buffer)
    selectedTrack = trialTrack // 成功！
    break
  } catch {
    console.warn(`${codecType} 编码不可用，尝试下一个`)
  }
}
```

**优势**：
- **avc1 优先**：Electron Chromium 硬解最佳选择
- **hevc 降级**：现代设备广泛支持（Windows/macOS/iOS）
- **any fallback**：绝对兜底策略
- **实际测试**：不仅通过 `isTypeSupported`，还要真正能 append

### 3️⃣ **canplaythrough 事件监听（双重保险）**

```typescript
const onCanPlayThrough = async () => {
  if (!videoEl.value || !currentView.value) return
  
  // 双重验证
  if (videoEl.value.readyState >= 3 && mediaSource?.readyState === 'open') {
    // 清理临时监听
    videoEl.value.removeEventListener('canplaythrough', onCanPlayThrough)
    videoEl.value.removeEventListener('loadedmetadata', onCanPlayThrough)
    
    // 延迟 100ms 确保内部状态稳定
    setTimeout(() => {
      // 优先执行 seek（如果有 pending 目标）
      if (seekSec > 0) {
        videoEl.value.currentTime = seekSec
        console.log(`[DASH] 延迟 seek 到 ${seekSec.toFixed(1)}s`)
      }
      
      // 最后触发 play()
      videoEl.value.play().catch(() => {
        console.warn('[DASH] autoplay 被拦截，等待用户手动播放')
      })
    }, 100)
  }
}

// 双保险监听
videoEl.value.addEventListener('canplaythrough', onCanPlayThrough, { once: true })
videoEl.value.addEventListener('loadedmetadata', onCanPlayThrough, { once: true })

// 超时 fallback（10 秒强制检查）
setTimeout(() => {
  if (videoEl.value.readyState >= 3 && mediaSource?.readyState === 'open') {
    onCanPlayThrough()
  }
}, 10000)
```

**关键参数说明**：
- `video.readyState >= 3`：对应 `HAVE_FUTURE_DATA`（浏览器保证可以流畅播放）
- `mediaSource.readyState === 'open'`：MSE 源已打开且有数据可播
- `setTimeout(100ms)`：确保内部状态机稳定后再操作
- `setTimeout(10000ms)`：防死锁兜底，避免事件丢失导致的无限等待

### 5️⃣ **MSE 配额管理与缓冲优化**

#### 主动清理历史区间（每轮 append 前）：
```typescript
evictOldBuffers(el: HTMLVideoElement, keepSeconds = 10): void {
  const keepBefore = Math.max(0, el.currentTime - keepSeconds)
  for (const b of dashBuffers) {
    if (b.updating || !b.buffered.length) continue
    for (let i = b.buffered.length - 1; i >= 0; i--) {
      const start = b.buffered.start(i)
      const end = Math.min(b.buffered.end(i), keepBefore)
      if (end > start + 1) b.remove(start, end)
    }
  }
}
```

**优势**：
- **保留回拖能力**：播放点前 10s 可快速跳转
- **释放配额压力**：防止 Chrome MSE 内存限制（~150MB）
- **减少碎片整理**：定期清理避免 buffer 区间断续
